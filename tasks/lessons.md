# 学んだこと

利用者から受けた修正を、直した日付ごとに記録する。各項目は「何が悪かったか」「規則」「どう適用するか」の順に書く。

## 2026-11-08

### 1. 依頼と返事の流れの説明で、誰が誰に送ったかを省いた

- 何が悪かったか: 依頼と返事の流れを説明するとき、送り手と受け手を書かずに「送った」「返した」とだけ書いた。読む人は、どの ConversationSquad アクターがどれに送ったのかを追えなかった。
- 規則: 依頼と返事の流れを説明するときは、送り手と受け手を、ConversationSquad アクターの番号（`chat-38` など）で必ず書く。省略しない。
- どう適用するか: 「`chat-38` が `chat-40` に依頼を送り、`chat-40` が `chat-38` に返事を返した」のように、文ごとに主語と宛先を書く。「上司」「作業役」だけで済ませない。

### 2. `chat-NN` を「会話」と呼んだ

- 何が悪かったか: `chat-38` のような名前の実体を「会話」と呼んだ。`chat-38` は、1 つの LLM セッションを司るアクターである。
- 規則: `chat-NN` の実体は「ConversationSquad アクター」と書く。
- どう適用するか: 文書、返事、コミットメッセージのどこでも、`chat-NN` を指すときは「ConversationSquad アクター」と書く。「会話」と書いてよいのは、画面の用語として会話そのものを指すときだけにする。

### 3. 「子の依頼」「子への依頼」という造語を作った

- 何が悪かったか: ある依頼のために別の ConversationSquad アクターへ送った依頼を、「子の依頼」「子への依頼」と呼んだ。この呼び名はどこにも定義が無く、読む人は何を指すのか分からなかった。
- 規則: やりとりの呼び名は「依頼」と「返事」だけにする。どの依頼のための依頼かは、文で書く。
- どう適用するか: 「`chat-38` が `chat-01` から受けた依頼のために、`chat-40` に送った依頼」のように書く。名前を縮めたくなったら、縮めずに文で書く。

### 4. コードを確かめずに、Claude Code のターンは agent loop を通らないと言い切った

- 何が悪かったか: 「Claude Code のターンは agent loop を通らない」と、コードを読まずに言った。間違いだった。実際は、どのプロバイダのターンも `PromptQueue.tryDispatch` から `ChatSession.start` と `runUntilEnd` を通り、agent loop で回る。
- 規則: 作りについて言い切る前に、呼び出しの経路を、入口から出口までコードでたどる。
- どう適用するか: 「通らない」「使わない」「できない」と書く前に、入口のメソッドから 1 つずつ呼び先を開き、通らないことを示す行を引く。経路をたどり終えていないときは、言い切らず「未確認」と書く。

### 5. 「後で報告します」という文言を、仕組みが文字列で探す案を出した

- 何が悪かったか: 返事の中の「後で報告します」を、仕組みが文字列として見つけ、催促を登録する案を出した。自然言語の意味の判断を、文字列の一致で代用する案である。言い回しが変われば外れる。
- 規則: 自然言語の意味の判断は、それを読む側のモデル（返事を受けた依頼元）に任せる。仕組みは、依頼 ID のような事実だけで結び付ける。
- どう適用するか: 新しい仕組みを考えるとき、「文面から何かを読み取る」段を仕組みの側に置かない。仕組みが持つのは、誰が誰に、どの依頼 ID で送ったかという事実だけにし、その事実を見せて判断するのはモデルにする。

### 6. 「ワークフロー」を修飾なしで使った

- 何が悪かったか: 3 種類ある YAML のどれを指すのか書かずに、「ワークフロー」と書いた。
- 規則: agent loop、プロンプト構築サブワークフロー、project workflow のどれかで書く。agent loop は小文字で書く。大文字の `Agent Loop` は、画面のタブ名のときだけ使う。
- どう適用するか: 「ワークフロー」と書きそうになったら、3 種類のどれかを選んで置き換える。一括置換するときは、タブ名の `Agent Loop` まで小文字にしていないか、差分を読んで確かめる（2026-11-08 の置換で 1 か所、`` `Agent Loop`タブ`` を小文字にしかけて戻した）。

### 7. 中断をまたいで引き継ぐ状態を、機能ごとの別の表に持った

- 何が悪かったか: ターンが中断されたあとも引き継ぐ状態を、機能ごとに別の表へ持たせた。その結果、1 つは載せ忘れ、別の 1 つは鍵が合わず取り出せなかった。
- 規則: あるターンが何のために動いていたかは、1 つの記録にまとめる。鍵は、中断したターンの ID にする。
- どう適用するか: 中断をまたいで引き継ぎたい状態を足すときは、新しい表を作らず、その 1 つの記録に項目を足す。取り出す側は、中断したターンの ID で引く。
